# RACE PROMPT EVOLUTION LOG

## 1. Purpose

Track changes to RACE prompt-generation instructions and standards.

## 2. Required Change Record

- Change identifier.
- Date.
- Affected prompt component or governing document.
- Source learning identifiers.
- Problem being addressed.
- Proposed change.
- Expected improvement.
- Potential regressions or trade-offs.
- Human approval.
- Implementation reference.
- Validation method.
- Validation result.

## 3. Change Dispositions

- PROPOSED
- APPROVED
- REJECTED
- DEFERRED
- IMPLEMENTED
- VALIDATED
- REVERTED

## 4. Version Control

Do not erase prior prompt versions or historical change decisions.

Record the relationship between old and new versions.

## 5. Validation

A change is not VALIDATED merely because it was implemented.

Record the evidence that demonstrates whether it improved results.

Where practical, compare the revised prompt against its predecessor using comparable missions and evaluation criteria.

## 6. Governing Rule

Prompt evolution must be evidence-driven, traceable, and human-authorized.
