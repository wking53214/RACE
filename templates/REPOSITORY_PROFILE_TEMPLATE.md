# 1. PURPOSE

Describe the repository's stated purpose.

# 2. CURRENT STATE

Record observed repository structure, major components, languages, and technologies.

# 3. EVIDENCE

Identify:
- Files inspected.
- Source locations.
- Tests examined.
- Tests executed.
- Build or runtime evidence.
- Inspection limitations.

# 4. CAPABILITIES

For each claimed capability identify:

- Capability.
- Implementation evidence.
- Verification status.
- Limitations.

# 5. ARCHITECTURE

Describe:
- Major components.
- Interfaces.
- Data flows.
- Internal boundaries.
- External connections.

# 6. DEPENDENCIES

Record direct, indirect, optional, runtime, development, and external dependencies.

Identify verification status.

# 7. SECURITY AND GOVERNANCE

Assess relevant:
- Authentication.
- Authorization.
- Trust boundaries.
- Data handling.
- Integrity controls.
- Auditability.
- Failure handling.

# 8. TESTING

Record:
- Test framework.
- Test inventory.
- Executed tests.
- Results.
- Failures.
- Skipped tests.
- Untested areas.

# 9. KNOWN LIMITATIONS

Identify incomplete, experimental, undocumented, or unverified capabilities.

# 10. INTEGRATION OPPORTUNITIES

Identify possible relationships with other systems.

Distinguish verified integrations from proposed integrations.

# 11. RISKS

Identify technical, operational, security, and dependency risks.

# 12. RECOMMENDATIONS

Use:

- KEEP
- INTEGRATE
- ADAPT
- PARTIAL
- SEPARATE
- DEFER
- REJECT
- NO ACTION

Support every material recommendation with evidence.

# 13. PROFILE CONCLUSION

Summarize what the repository demonstrably does, what it may do, and what remains unknown.
